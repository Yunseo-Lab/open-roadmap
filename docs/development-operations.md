# Open Roadmap Development and Operations

This document explains how to run, verify, and operate the current codebase.

## Repository Layout

```text
src/
  backend/          Cloudflare Worker backend, Hono routes, D1/R2 access
  frontend/         Active React frontend app
  shared/           Shared graph/domain types and validation
services/
  ai/               Optional Python AI service contract
migrations/         D1 migrations
docs/               Architecture and contributor documentation
dist/client/        Built frontend assets generated by the build
```

The active frontend is `src/frontend`. `src/frontend_mvp` is not part of the
current build path.

## Runtime Pieces

| Piece | Local command | Default port | Notes |
| --- | --- | --- | --- |
| Worker/API/assets preview | `npm run preview` | `8787` | Builds frontend, then runs Wrangler locally. |
| Worker/API only | `npm run dev` | `8787` | Runs `wrangler dev --local`; requires existing assets for non-API routes. |
| Frontend package dev server | `npm --prefix src/frontend run dev` | `5174` | Proxies `/api` to `127.0.0.1:8787`. |
| Optional Python AI service | `uvicorn app.main:app --reload --port 8000` | `8000` | Used only when `AI_SERVICE_URL` is set. |

For most full-stack work, use `npm run preview`. Use the package-local
frontend dev server when iterating on UI and running a separate Worker API.

## Initial Setup

```bash
npm install
npm run cf-typegen
cp .dev.vars.example .dev.vars
npm run db:migrate:local
```

If `.dev.vars.example` is absent, create `.dev.vars` with only the local values
you need. Do not commit secrets.

Local development works without Google OAuth because the backend creates and
returns `dev-user` when `APP_ENV` is not `production`.

## Environment and Bindings

`wrangler.jsonc` declares:

| Binding or var | Kind | Purpose |
| --- | --- | --- |
| `DB` | D1 binding | Users, roadmaps, graph data, artifacts, AI tables. |
| `FILES` | R2 binding | Uploaded file objects. |
| `ASSETS` | Workers Assets binding | Built frontend under `dist/client`. |
| `APP_ENV` | var | `development` enables dev user fallback. |
| `BETTER_AUTH_URL` | var | Base URL for Better Auth and OpenRouter referer. |
| `OPENROUTER_MODEL` | var | Worker-side AI model name. |
| `AI_SERVICE_URL` | var | Optional Python service base URL. |
| `BETTER_AUTH_SECRET` | secret | Required in production. |
| `GOOGLE_CLIENT_ID` | secret | Enables Google login with client secret. |
| `GOOGLE_CLIENT_SECRET` | secret | Enables Google login with client ID. |
| `OPENROUTER_API_KEY` | secret | Enables real Worker-side OpenRouter agent. |

Production secrets should be set with Wrangler:

```bash
npx wrangler secret put BETTER_AUTH_SECRET
npx wrangler secret put GOOGLE_CLIENT_ID
npx wrangler secret put GOOGLE_CLIENT_SECRET
npx wrangler secret put OPENROUTER_API_KEY
```

`AI_SERVICE_URL` is usually an environment var, not a secret.

## Database Migrations

Local D1:

```bash
npm run db:migrate:local
```

Remote D1:

```bash
npm run db:migrate:remote
```

Current migrations:

| Migration | Purpose |
| --- | --- |
| `0001_initial.sql` | Auth tables, profiles, roadmaps, graph nodes/edges, artifacts, AI conversation/run tables. |
| `0002_graph_type_definitions.sql` | Per-roadmap node/edge type definition tables and removal of fixed graph type checks. |

When adding schema:

1. Add a new migration file under `migrations/`.
2. Update backend row types and query helpers.
3. Update docs for data model or graph contract changes.
4. Apply locally and run tests.

## Verification Strategy

Use the narrowest useful check:

| Change type | Recommended check |
| --- | --- |
| Shared graph validation | `npm test` |
| Frontend graph adapter | `npm test` |
| Backend route/type changes | `npm run build` and targeted manual API check |
| Frontend screen changes | `npm run build`, then browser check through preview or frontend dev server |
| D1 migration changes | `npm run db:migrate:local`, then route exercising affected tables |
| Python service changes | Service-level Python tests if added, then Worker call through `AI_SERVICE_URL` |
| Docs-only changes | Link/path review and optionally `npm test` to confirm no code drift |

Current test files:

- `src/shared/graph.test.ts`
- `src/frontend/src/app/graph/adapter.test.ts`

## Local Full-Stack Runbook

1. Install dependencies:

   ```bash
   npm install
   ```

2. Generate Cloudflare types:

   ```bash
   npm run cf-typegen
   ```

3. Apply local migrations:

   ```bash
   npm run db:migrate:local
   ```

4. Start preview:

   ```bash
   npm run preview
   ```

5. Open:

   ```text
   http://127.0.0.1:8787
   ```

The first `/api/me` call should create or return the development user unless
`APP_ENV=production`.

## Frontend-Only Runbook

Use this when you want Vite HMR for `src/frontend`:

1. Start the Worker API:

   ```bash
   npm run dev
   ```

2. In another terminal, start the frontend package:

   ```bash
   npm --prefix src/frontend run dev
   ```

3. Open:

   ```text
   http://127.0.0.1:5174
   ```

`src/frontend/vite.config.ts` proxies `/api` to `http://127.0.0.1:8787`.

## Python AI Service Runbook

```bash
cd services/ai
python -m venv .venv
source .venv/bin/activate
pip install -e .
uvicorn app.main:app --reload --port 8000
```

Then set:

```text
AI_SERVICE_URL=http://localhost:8000
```

and start the Worker. Calls to `/api/roadmaps/:id/agent/messages` will delegate
to the Python service.

## Deployment Checklist

Before deploying:

1. Confirm `wrangler.jsonc` has the intended D1 database ID and R2 bucket name.
2. Apply remote migrations with `npm run db:migrate:remote`.
3. Set production secrets with `wrangler secret put`.
4. Set `APP_ENV=production`.
5. Set `BETTER_AUTH_URL` to the public Worker/app URL.
6. Configure Google OAuth redirect URLs for Better Auth routes.
7. Decide whether `AI_SERVICE_URL` or Worker-side OpenRouter should handle AI.
8. Run `npm run build`.
9. Deploy with the repository's chosen Wrangler deployment command.

## Troubleshooting

| Symptom | Likely cause | Check |
| --- | --- | --- |
| `/api/me` returns `401` locally | `APP_ENV=production` or auth session missing | Use development env or sign in. |
| Roadmap pages 404 after frontend refresh | Assets fallback not serving SPA | Check `wrangler.jsonc` assets `not_found_handling`. |
| Upload rejected | File too large or unsupported MIME | See `src/backend/services/artifacts.ts`. |
| Artifact attach fails | Graph not saved before attach | Ensure `ensureGraphSaved` runs first. |
| AI endpoint returns missing key error | `OPENROUTER_API_KEY` absent in production | Set secret or configure `AI_SERVICE_URL`. |
| AI endpoint uses fallback | No OpenRouter key in development | Expected unless key or Python service is configured. |
| Public file not visible | Artifact not selected during publish | Check artifact `is_public` after publish. |
| Graph save fails with unsupported type | Frontend sent a type not present in graph type definitions | Check adapter and type definitions. |

## Generated and External Directories

Do not hand-edit these as source of truth:

- `dist/client`: generated frontend build output.
- `node_modules`: root dependencies.
- `src/frontend/node_modules`: frontend package dependencies.
- local Wrangler/D1 state directories if created by Wrangler.
